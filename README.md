# SFP + MSS Bot

Сканер сетапов SFP (Swing Failure Pattern) + MSS (Market Structure Shift)
по фьючерсам OKX (SWAP), сигналы уходят в Telegram. Запуск по расписанию
через GitHub Actions (`.github/workflows/bot.yml`, каждые 15 минут).

## Режим качества сигналов

Бот настроен на «меньше сигналов, но сильнее»:

- только трендовые сетапы по 4H, контртренд отключён
  (`ENABLE_COUNTER_TREND_SIGNALS = False`);
- MSS засчитывается только как пробой LH (лонг) / HL (шорт) после
  свипа ликвидности - пробой HH/LL это продолжение тренда, а не сдвиг;
- displacement свечи MSS - минимум 0.50 ATR, объём на пробое -
  обязательное подтверждение (минимум 1.2x от среднего);
- сигнал живёт не дольше 2 свечей после MSS (`MAX_SIGNAL_AGE_BARS`),
  цена должна удерживать уровень пробоя, стоп не должен быть уже
  касавшимся после MSS;
- минимальные пороги качества по компонентам: SFP и MSS score >= 70,
  итоговый score >= 80;
- цели считаются от крупных свингов (окно 10/10), но ограничены
  кратными риска: TP1 - не дальше 1R, TP2 - не дальше 2R;
- риск: маржа не может превышать баланс, стоп обязан стоять заметно
  раньше расчётной ликвидации;
- один и тот же сетап никогда не отправляется дважды (отпечаток
  SFP+MSS в `data/signals_state.json`), плюс кулдаун по символу.
- анти-погоня: входа нет, если цена уже прошла больше 2.5 ATR в
  сторону сделки за последние 20 свечей - вход на истощении был
  главным источником убытков по разбору бэктеста за 6 месяцев;
- безубыток: после +1R стоп переносится в точку входа (правило есть
  и в тексте сигнала, и в модели бэктеста);
- окно дистанции на 4H: вход только когда цена старшего ТФ в
  пределах [-0.5, +1.5] ATR от своей EMA50 - движение началось,
  но не выдохлось;
- режим широкого рынка (`ENABLE_REGIME_FILTER`): направление
  сделки задаёт BTC на дневке - лонг только когда BTC выше
  своей EMA50, шорт только когда ниже. Шорты без этого условия
  убыточны (PF 0.77-0.87), с ним режимный бот в обе стороны
  на 12 месяцах (окт 2025 - окт 2026) дал 170 сделок, +8.93R,
  winrate 56%, PF 1.12 (падающее окно -2.40R, растущее
  +11.33R). Предыдущая лонговая версия на том же падающем
  окне дала -33.10R.

Все пороги лежат в `config.py`.

## Бэктест

Walk-forward проверка той же логики на истории OKX без look-ahead:

```bash
python backtest.py --symbols BTC-USDT,ETH-USDT --bars 3000 --csv trades.csv
```

Показывает число сделок, winrate, средний и суммарный R, profit factor
и максимальную просадку. Бэктест - инструмент проверки логики, а не
гарантия доходности: «только правильных» сигналов не существует.


## Настройка

Секреты в GitHub Actions: `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`.
Баланс, риск и плечо для расчёта позиции: `data/user_settings.json`.
